# Libreno

**チームの情報を、AIと一緒に育てる場所。**

Librenoは小さなチームのための情報共有ツールです。チームで共有したいことは種類を問わず1か所にまとめておけます。

AIが書いて、チームが読む。これがLibrenoの基本の考え方です。

### 書くのはAIに任せる

ClaudeなどのアプリからMCPで接続して「経費申請の手順をまとめて」と頼めば、AIがページを書いて保存します。既存のページを読んで直すことも関係するページを探すこともAIに任せられます。本文はMarkdownなのでAIが書いたものをそのまま置けます。

### 読む人はブラウザで開くだけ

チームの人はWebでページを読んだり検索したりします。ページを開いたときは読むための表示なので、うっかり書き換えることはありません。直したいときは編集ボタンから編集できます。

### 見せる相手はスペースで分ける

スペースごとに見られる人を分けられます。全員が見られるスペース、管理者だけが見られるスペース（経理や人事など）、本人だけが見られるスペース（個人のメモ）の3種類です。AIもWebと同じ権限で動くので、見られないページをAIが読むことはありません。

### 自分たちのCloudflareアカウントで動く

Cloudflare Workers・D1・R2の上で動きます。「Deploy to Cloudflare」ボタンで自分のアカウントにデプロイでき、データは自分のD1とR2に置かれます。

## デプロイする

**デプロイの前にCloudflareのダッシュボードでR2を有効にしてください（R2のサブスクリプションを追加します）。** 添付ファイルの保存にR2を使うので、有効にしていないとデプロイが失敗します。

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/i2bskn/libreno)

ボタンを押すと次のことが行われます。

1. このリポジトリがあなたのGitHubに新しいリポジトリとしてコピーされます（forkではありません）。
2. D1データベースとKVネームスペース（MCPの接続情報を保存）とR2バケット（添付ファイルを保存）が、あなたのCloudflareアカウントに1つずつ作られてWorkerに紐付きます。
3. Workers Buildsが設定されてマイグレーションの適用とデプロイが行われます。以降はコピーされたリポジトリへpushするたびにデプロイされます。

Web画面（React）は`wrangler.jsonc`の`build.command`で`wrangler deploy`の前に自動でビルドされます。Workers Buildsでビルドコマンドを設定する必要はありません。

デプロイには`pnpm run deploy`（`scripts/deploy.mjs`）が使われます。マイグレーションを適用してから`wrangler deploy`を実行し、新しいコードが動く前に表ができているようにします。初回でD1がまだないときだけは、D1・KV・R2を自動で作る`wrangler deploy`を先に実行してからマイグレーションを適用します（`wrangler d1 migrations apply`は既存のD1を探すだけで、作らないため）。表ができるまでの数秒間はWorkerが表のない状態で動きますが、まだ誰も使っていないので影響はありません。

セットアップ画面では`JWT_SECRET`を入力します。`openssl rand -hex 32`で生成した値を使ってください。変更すると全員がログアウトします。

デプロイ直後はパスワード認証で動きます。表示されたURLを開くと初期設定画面になり、**最初に登録した人が管理者になります**。URLを知った他人に先に登録されないように、デプロイしたらすぐ登録してください。

### 動作環境

- Workersの無料プランで動きます。ただしパスワードのハッシュ（PBKDF2を10万回）にCPU時間を1回16〜32ms使うので、無料プランの上限（1リクエスト10ms）を超えます。ログインがCPU時間の上限で失敗する場合はWorkers Paidを使ってください。
- MCPは接続するたびにCPU時間を20〜40ms使い、ファイルの添付では1回60ms以上使うこともあるので、無料プランの上限を超えます。MCPを使う場合はWorkers Paidを使ってください。
- Webからの添付ファイルのアップロードは10MBのファイルでもCPU時間が4〜7msで、無料プランの上限に収まります（ファイルをメモリに読まずにR2へ流すため）。
- そのページへリンクしているページを探すため、ページを開くたびに見られるページの本文をすべてD1から読みます（読み取り行数は1回あたりページ数とほぼ同じです）。ページが1,000件なら、1日5,000回ページを開くと無料プランの上限（1日500万行）に達します。
- Cron Triggerを1日1回使い、ゴミ箱に30日あったページと持ち主のなくなった添付ファイルを消します。Workersの無料プランでも使えますが、アカウントあたりのCron Triggerの上限のうち1つを使います。消すものがない日でもCPU時間を11ms使ったので（1回の計測）、無料プランの上限（1回10ms）を超えて失敗することがあります。失敗しても次の日の実行で同じものを消します。失敗が続く場合はWorkers Paidを使ってください。
- プレビューURLは無効にしています。マイグレーションを適用していないコードが本番のD1に触れるのを防ぐためです。

## 設定

設定はCloudflareのダッシュボードの「設定」→「変数とシークレット」で行います。`wrangler.jsonc`で`keep_vars: true`を指定しているので、ダッシュボードで設定した値は再デプロイしても消えません。変数は「テキスト」の型で設定してください。

| 名前 | 種類 | 内容 |
| --- | --- | --- |
| `JWT_SECRET` | シークレット | 必須。32文字以上 |
| `AUTH_MODE` | 変数 | `password`（既定）または`oidc` |
| `APP_ORIGIN` | 変数 | `oidc`のとき必須。ブラウザで開くOrigin（例: `https://wiki.example.com`） |
| `OIDC_ISSUER` | 変数 | `oidc`のとき必須。IdPのissuer |
| `OIDC_CLIENT_ID` | 変数 | `oidc`のとき必須 |
| `OIDC_CLIENT_SECRET` | シークレット | `oidc`のとき必須 |
| `ALLOWED_EMAILS` | 変数 | 任意。ログインを許可するメールのドメインと個別のメールアドレス（カンマ区切り） |
| `OIDC_REQUIRE_EMAIL_VERIFIED` | 変数 | 任意。`false`にするとIDトークンに`email_verified`が含まれない場合に限ってログインを通します |

設定に誤りがあると、すべてのリクエストが500になります。

### OIDC認証にする

OIDC認証では初回ログイン時にユーザーが自動で作られます。誰がログインできるかはIdP側で絞ってください。IdPのアカウントを持つ人なら誰でもログインできる構成（Googleの同意画面を「外部」で作った場合など）では、必ず`ALLOWED_EMAILS`を設定してください。

IdPにはリダイレクトURLとして`<APP_ORIGIN>/auth/oidc/callback`を設定し、スコープには`openid`と`email`と`profile`を設定します。

Cloudflare Accessを使う場合は、Access for SaaSのOIDCアプリとして登録します（Accessをアプリの前に置く構成には対応していません）。AccessのIDトークンには`email_verified`が含まれないので、`OIDC_REQUIRE_EMAIL_VERIFIED`を`false`にしてください。この設定を使うのは、Accessのログイン方法がすべてメールを検証済みのIdP（Googleなど）である場合だけにしてください。既存のユーザーとはメールアドレスで紐付くので、メールを検証しないログイン方法があると他人のアカウントに入れてしまいます。

## ユーザーを管理する

管理者はWebの「ユーザー管理」（`/users`）でユーザーの一覧を見られます。ここではロールを変えたり、ログアウトさせたり、ユーザーを削除したりできます。パスワード認証ではユーザーの追加とパスワードの再設定もできます。

- ユーザーを削除すると、その人の個人スペースも中身（ページ・ゴミ箱のページ・フォルダ・添付ファイル）ごと削除されます。元に戻せません。D1をTime Travelで戻しても、R2から消えた添付ファイルは戻りません。
- ほかのスペースでその人が作成・編集したページは残ります。
- 自分自身は削除できません。最後の管理者を削除することも一般に戻すこともできません。
- OIDC認証の場合、IdPでその人のログインを止めるか`ALLOWED_EMAILS`から外さない限りその人はまたログインできます。そのときは新しいユーザーとして作られます。

## Webで表示・編集する

Web画面でページの本文（Markdown）を表示するときは、本文中のHTMLをタグとして解釈せずに書いたとおりの文字で表示します。外部の画像は表示しません。

Webでページを作成・編集している間は、入力中の内容がブラウザ（localStorage）に下書きとして保存されます。この下書きはログアウトしても消えないので、同じブラウザでログインした別の人に見える可能性があります。同じページを複数のタブで編集すると下書きどうしが上書きし合います。共有PCでは使わないでください。

## 添付ファイル

ページには画像（PNG・JPEG・GIF・WebP）とPDFを添付できます。Webではページの編集画面の「添付ファイル」から追加して（1ファイル10MBまで）、本文にMarkdownとして挿入できます。新しいページは保存してから編集画面で添付してください。MCPからも添付できます（1ファイル2MBまで）。

- ファイルの種類は中身から判定します。SVGやHTMLのようにスクリプトを含められる形式は添付できません。ファイル名の拡張子が種類と合わないときは種類の拡張子を末尾に足します。
- 添付ファイルを見られるのはそのページを見られる人だけです。ページを別のスペースへ移すと添付ファイルも一緒に移ります。
- ゴミ箱にあるページの添付ファイルは見られません。ページを元に戻すとまた見られるようになります。
- 添付ファイルの削除は元に戻せません。本文から参照している箇所は表示されなくなります。
- ファイルの中身はR2に保存します。ページを完全に削除すると添付ファイルもR2から削除されます。30日たって自動で削除されたページの添付ファイルは、ページと同じ日次の処理で消えます。管理者がゴミ箱から完全に削除したページの添付ファイルは、次の日次の処理（毎日03:00 JST）で消えます。アップロードの途中で失敗して残ったファイルは、24時間たったあとの日次の処理で消えます。

## トップページ

ホーム画面（`/`）ではスペースの一覧の上にページを1つ表示できます。管理者が全員スペースのページを開いて「トップに表示」を押すと、そのページが全員のホーム画面に出ます。リンク集のようにチームの入口になるページに向いています。

- 選べるのは全員スペースのページだけです。表示中のページを全員スペース以外へ移したりゴミ箱に入れたりすると表示されなくなり、戻すとまた表示されます。
- ページを完全に削除すると設定も外れます。
- 表示するページはほかのページと同じように編集できます。MCPからも`update_page`で更新できます。どのページを表示するかはWebでしか選べません。

## ページどうしのリンク

ページの末尾の「このページへのリンク」には、本文でそのページへリンクしているページが並びます。出るのは見ている人が見られるページのうちゴミ箱にないものだけです（新しく更新された50件まで）。

- ページの「リンクをコピー」を押すと`[タイトル](/pages/{id})`の形のMarkdownがコピーされます。ほかのページの本文に貼り付けてください。
- 本文に`/pages/{id}`を含むものはすべてリンクとして数えます。`https://…/pages/{id}`のような完全なURLも、コードブロックの中も含みます。
- MCPではAIが`[タイトル](/pages/{id})`の形でリンクを書きます。リンクしているページを探すときは`search_pages`で`/pages/{id}`を検索します。この検索結果には、タイトルが一致したページとそのページ自身も含まれます。

## MCPで接続する

生成AIのアプリからMCPでスペースとページを読み、ページを作成・更新できます。ページのタイトルと本文を文字列で検索することもできます。接続はログインしたユーザー本人として行われます。Webと同じく、そのユーザーがアクセスできるスペースしか見えません。

フォルダの作成・名前変更・移動・削除もMCPからできます。削除できるのは、中にフォルダと（ゴミ箱以外の）ページがないフォルダだけです。

ページとフォルダは移動用のツール（`move_page`と`move_folder`）で別のスペースへ移せます。フォルダは中のフォルダとページ（ゴミ箱のページを含む）ごと移ります。個人スペースから全員スペースへのように見られる人が増える移動では、AIが利用者に確認してから`acknowledge_wider_visibility`を付けて呼ばないと失敗します。

MCPからはページへのファイルの添付（`upload_attachment`、2MBまで）と添付ファイルの一覧（`list_attachments`）も使えます。添付したファイルを本文に入れるには、返されたMarkdownを`update_page`で本文に書き足します。添付ファイルの削除はWebからしかできません。

MCPからページを削除するとゴミ箱に移り、30日のあいだは元に戻せます。完全に削除できるのは管理者だけで、Webのゴミ箱から行います。上書きする前の内容は編集履歴として新しい20版まで残り、そこから戻せます。ゴミ箱から完全に削除したページと30日たって自動で削除されたページは、履歴ごと消えるので戻せません。

接続先のURLは`<URL>/mcp`です（OIDC認証では`<APP_ORIGIN>/mcp`）。Claudeのカスタムコネクタで追加する手順は次のとおりです。

1. Claudeの「設定」→「コネクタ」でカスタムコネクタを追加する。
2. URLに`<URL>/mcp`を入れて接続する。
3. 開いたブラウザでlibrenoにログインし、接続を許可する。

Claude Codeで追加する手順は次のとおりです。OIDC認証では`<URL>/mcp`の代わりに`<APP_ORIGIN>/mcp`を使います。

1. `claude mcp add --transport http libreno <URL>/mcp`を実行する。
2. Claude Codeで`/mcp`を開き、librenoを選んで認証する。
3. 開いたブラウザでlibrenoにログインし、接続を許可する。

許可の画面は接続のたびに表示されます。接続の有効期限はOIDC認証で24時間、パスワード認証で30日です。期限が切れたらもう一度接続してください。

管理者がユーザーのセッションを失効させたとき、管理者がパスワードを再設定したとき、本人がパスワードを変更したときは、そのユーザーのMCPの接続もすべて切れます。ただし接続情報を保存しているKVは別の拠点への反映が遅れるので、失効の直前（最大60秒ほど）に作られた接続は切れずに残ることがあります。その場合はもう一度失効させてください。Webからログアウトしても、MCPの接続は切れません。

デプロイすると、MCPの接続情報を保存するKVネームスペースが1つ作られます。

## 更新する

ボタンで作ったリポジトリには、このリポジトリの更新が自動では届きません。次の手順で取り込んでください。pushするとWorkers Buildsがマイグレーションを適用してからデプロイします。

```sh
git remote add upstream https://github.com/i2bskn/libreno.git  # 初回だけ
git fetch upstream
git merge upstream/main
git push
```

`wrangler.jsonc`を自分で変更している場合は、マージで競合することがあります。

**添付ファイルの機能が入る前の版から更新するときも、先にCloudflareのダッシュボードでR2を有効にしてください。** R2を有効にせずに更新してデプロイが失敗したときは、R2を有効にしてから再デプロイすれば動きます。先に適用されたマイグレーションは表を追加するだけなので、そのままで問題ありません。

## バックアップ

バックアップは各自で行ってください。D1はTime Travelで過去の時点に戻せます。`wrangler d1 export`でSQLとして書き出すこともできます。

## ローカルで開発する

Node.jsとpnpmが必要です。

```sh
pnpm install
cp .dev.vars.example .dev.vars   # JWT_SECRET を設定する
pnpm db:migrate:local
pnpm dev
```

`pnpm dev`はWeb画面（`client/`）をビルドしてから`wrangler dev`を起動します。`client/`のファイルを変えると自動で再ビルドされます。HMRは無いので、ブラウザを再読み込みしてください。

CookieにSecure属性と`__Host-`接頭辞を使っているので、`http://localhost`ではSafariでログインできません。ChromeかFirefoxを使ってください。

| コマンド | 内容 |
| --- | --- |
| `pnpm test` | テスト |
| `pnpm typecheck` | 型チェック（サーバーとWeb画面） |
| `pnpm build:client` | Web画面を`dist/client`にビルドする |
| `pnpm db:generate` | スキーマからマイグレーションを作る |
| `pnpm run deploy` | 本番のD1にマイグレーションを適用してデプロイする（`pnpm deploy`はpnpm自体のコマンドなので`run`を付けてください）。Cloudflareのアカウントが複数あるときは`CLOUDFLARE_ACCOUNT_ID`にデプロイ先のアカウントIDを指定してください |
