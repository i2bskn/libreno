# Libreno

**チームの情報を、AIと一緒に育てる場所。**

Librenoは小さなチームのための情報共有ツールです。チームで共有したいことは種類を問わず1か所にまとめておけます。

AIが書いて、チームが読む。これがLibrenoの基本の考え方です。

### 書くのはAIに任せる

ClaudeなどのアプリからMCPで接続して「経費申請の手順をまとめて」と頼めば、AIがページを書いて保存します。既存のページを読んで直すことも関係するページを探すこともAIに任せられます。本文はMarkdownなのでAIが書いたものをそのまま置けます。

### 読む人はブラウザで開くだけ

チームの人はWebでページを読んだり検索したりします。ページを開いたときは読むための表示なので、うっかり書き換えることはありません。直したいときは編集ボタンから編集できます。

### 見せる相手はスペースで分ける

スペースごとに見られる人を分けられます。種類は4つです。

- 全員が見られるスペース
- 管理者だけが見られるスペース（経理や人事など）
- 管理者が選んだメンバーと管理者が見られるスペース（プロジェクトのチームなど）
- 本人だけが見られるスペース（個人のメモ）

AIもWebと同じ権限で動くので、見られないページをAIが読むことはありません。

### 自分たちのCloudflareアカウントで動く

Cloudflare Workers・D1・R2の上で動きます。「Deploy to Cloudflare」ボタンで自分のアカウントにデプロイでき、データは自分のD1とR2に置かれます。

## デプロイする

**デプロイの前にCloudflareのダッシュボードでR2を有効にしてください（R2のサブスクリプションを追加します）。** 添付ファイルの保存にR2を使うので、有効にしていないとデプロイが失敗します。

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/i2bskn/libreno)

ボタンを押すと次のことが行われます。

1. このリポジトリがあなたのGitHubに新しいリポジトリとしてコピーされます（forkではありません）。
2. D1データベースとKVネームスペース（MCPの接続情報を保存）とR2バケット（添付ファイルを保存）が、あなたのCloudflareアカウントに1つずつ作られてWorkerに紐付きます。
3. Workers Buildsが設定されてマイグレーションの適用とデプロイが行われます。以降はコピーされたリポジトリへpushするたびにデプロイされます。

Web画面（React）は`wrangler.jsonc`の`build.command`で`wrangler deploy`の前に自動でビルドされます。Workers Buildsでビルドコマンドを設定する必要はありません。

デプロイには`pnpm run deploy`（`scripts/deploy.mjs`）が使われます。マイグレーションを適用してから`wrangler deploy`を実行し、新しいコードが動く前に表ができているようにします。初回でD1がまだないときだけは、D1・KV・R2を自動で作る`wrangler deploy`を先に実行してからマイグレーションを適用します（`wrangler d1 migrations apply`は既存のD1を探すだけで、作らないため）。表ができるまでの数秒間はWorkerが表のない状態で動きますが、まだ誰も使っていないので影響はありません。

セットアップ画面では`JWT_SECRET`を入力します。`openssl rand -hex 32`で生成した値を使ってください。変更すると全員がログアウトします。

デプロイ直後はパスワード認証で動きます。表示されたURLを開くと初期設定画面になり、**最初に登録した人が管理者になります**。URLを知った他人に先に登録されないように、デプロイしたらすぐ登録してください。

### 動作環境

- Workersの無料プランで動きます。ただしパスワードのハッシュ（PBKDF2を10万回）にCPU時間を1回16〜32ms使うので、無料プランの上限（1リクエスト10ms）を超えます。ログインがCPU時間の上限で失敗する場合はWorkers Paidを使ってください。
- MCPは接続するたびにCPU時間を20〜40ms使い、ファイルの添付では1回60ms以上使うこともあるので、無料プランの上限を超えます。MCPを使う場合はWorkers Paidを使ってください。
- Webからの添付ファイルのアップロードは10MBのファイルでもCPU時間が4〜7msで、無料プランの上限に収まります（ファイルをメモリに読まずにR2へ流すため）。
- そのページへリンクしているページを探すため、ページを開くたびに見られるページの本文をすべてD1から読みます（読み取り行数は1回あたりページ数とほぼ同じです）。ページが1,000件なら、1日5,000回ページを開くと無料プランの上限（1日500万行）に達します。
- Cron Triggerを1日1回使い、ゴミ箱に30日あったページと持ち主のなくなった添付ファイルを消します。Workersの無料プランでも使えますが、アカウントあたりのCron Triggerの上限のうち1つを使います。消すものがない日でもCPU時間を11ms使ったので（1回の計測）、無料プランの上限（1回10ms）を超えて失敗することがあります。失敗しても次の日の実行で同じものを消します。失敗が続く場合はWorkers Paidを使ってください。
- ページのPDF出力をサーバーで行う場合（`PDF_RENDERER=browser`）はBrowser Rendering（Browser Run）を使います。無料プランではブラウザを使える時間が1日10分までです。超えるとその日はサーバーでPDFを作れないので、ブラウザの印刷を使ってください。Browser Runの利用量はアカウント内のほかのWorkerと共有されます。
- プレビューURLは無効にしています。マイグレーションを適用していないコードが本番のD1に触れるのを防ぐためです。

## 設定

設定はCloudflareのダッシュボードの「設定」→「変数とシークレット」で行います。`wrangler.jsonc`で`keep_vars: true`を指定しているので、ダッシュボードで設定した値は再デプロイしても消えません。変数は「テキスト」の型で設定してください。

| 名前 | 種類 | 内容 |
| --- | --- | --- |
| `JWT_SECRET` | シークレット | 必須。32文字以上 |
| `AUTH_MODE` | 変数 | `password`（既定）または`oidc` |
| `APP_ORIGIN` | 変数 | ブラウザで開くOrigin（例: `https://wiki.example.com`）。`oidc`のとき必須。`password`ではパスキー（WebAuthn）を使う場合に必要 |
| `OIDC_ISSUER` | 変数 | `oidc`のとき必須。IdPのissuer |
| `OIDC_CLIENT_ID` | 変数 | `oidc`のとき必須 |
| `OIDC_CLIENT_SECRET` | シークレット | `oidc`のとき必須 |
| `INITIAL_ADMIN_EMAIL` | 変数 | `oidc`で使います。ユーザーがまだいないときに、このメールアドレスでログインした人が最初の管理者になります。ユーザーが1人でもいれば使われません |
| `OIDC_REQUIRE_EMAIL_VERIFIED` | 変数 | 任意。`false`にするとIDトークンに`email_verified`が含まれない場合に限ってログインを通します |
| `OIDC_REQUIRE_GOOGLE_HD` | 変数 | 任意。`oidc`で`true`にすると、初回ログイン（招待したユーザーとの紐付けと最初の管理者の作成）で、`@gmail.com`以外のアカウントにはIDトークンの空でない`hd`（Google Workspaceのドメイン）を必須にします。IdPがGoogle（またはGoogleだけを使うCloudflare Access）のときだけ使ってください。`true`と`false`以外の値では初回ログインを拒否します（500にはなりません） |
| `SESSION_MAX_AGE_HOURS` | 変数 | 任意。Webのログインが続く上限（ログインからの時間数）。`1`〜`9600`。未設定なら`password`で720（30日）、`oidc`で24 |
| `SESSION_IDLE_TIMEOUT_HOURS` | 変数 | 任意。Webを使わないままでいるとログアウトされるまでの時間数。`1`〜`9600`。使うたびに`SESSION_MAX_AGE_HOURS`の上限まで延びます。未設定なら使っていてもいなくても`SESSION_MAX_AGE_HOURS`で切れます |
| `PASSWORD_MFA_POLICY` | 変数 | 任意。`password`での多要素認証の要否。`optional`（既定。各自が任意で設定）・`admins`（管理者は必須）・`all`（全員必須） |
| `PASSWORD_MFA_KEY` | シークレット | 任意。`password`で認証アプリ（TOTP）を使う場合に設定します。`openssl rand -base64 32`で生成した値を使ってください。変えると登録済みの認証アプリが使えなくなります |
| `PDF_RENDERER` | 変数 | 任意。`browser`にするとページのPDFをサーバー（Browser Rendering）で作ります。未設定ならブラウザの印刷機能を使います |

設定に誤りがあると、すべてのリクエストが500になります。たとえば次の場合です。

- `PASSWORD_MFA_POLICY`が`optional`・`admins`・`all`のどれでもない。
- `PASSWORD_MFA_POLICY`が`admins`か`all`なのに、有効なHTTPSの`APP_ORIGIN`も`PASSWORD_MFA_KEY`もない（多要素認証を登録する方法がない）。
- `PASSWORD_MFA_KEY`が32バイトのbase64（`openssl rand -base64 32`の出力）ではない。
- `INITIAL_ADMIN_EMAIL`がメールアドレスとして正しくない。

`OIDC_REQUIRE_GOOGLE_HD`は例外で、誤った値では初回ログインだけを拒否します。

`SESSION_MAX_AGE_HOURS`を変えると、次にログインしたときから効きます。`SESSION_IDLE_TIMEOUT_HOURS`はログイン中の人にもすぐに効きます。たとえば`SESSION_IDLE_TIMEOUT_HOURS`を`168`、`SESSION_MAX_AGE_HOURS`を`720`にすると、7日使わなければログアウトされ、使い続けていても30日でログインし直すことになります。

### OIDC認証にする

OIDC認証は招待制です。ログインできるのは、管理者が「ユーザー管理」で追加した人だけです。

- ユーザーがまだいないときは、`INITIAL_ADMIN_EMAIL`のメールアドレスでログインした人が最初の管理者になります。`INITIAL_ADMIN_EMAIL`を設定しないと、誰もログインできません。
- 2人目からは、管理者が「ユーザー管理」でメールアドレスとロールを登録します。登録された人が初回ログインすると、メールアドレスが一致した登録ユーザーにIdPのアカウントが紐付きます。2回目からはIdPのアカウントで本人を判定し、メールアドレスは見ません。
- 登録されていないメールアドレスでログインすると403になり、ユーザーは作られません。

IdPにはリダイレクトURLとして`<APP_ORIGIN>/auth/oidc/callback`を設定し、スコープには`openid`と`email`と`profile`を設定します。

Cloudflare Accessを使う場合は、Access for SaaSのOIDCアプリとして登録します（Accessをアプリの前に置く構成には対応していません）。AccessのIDトークンには既定では`email_verified`が含まれないので、`OIDC_REQUIRE_EMAIL_VERIFIED`を`false`にしてください。この設定を使うのは、Accessのログイン方法がすべてメールを検証済みのIdP（Googleなど）である場合だけにしてください。招待したユーザーとはメールアドレスで紐付くので、メールを検証しないログイン方法があると他人のアカウントに入れてしまいます。

AccessのOIDCアプリの設定にある「Add claims」で、Google IdPから取り込んだ`verified_email`を`email_verified`としてIDトークンに渡すと、`OIDC_REQUIRE_EMAIL_VERIFIED=false`を使わずに済む場合があります。値が真偽値の`true`で届くかはIdPとAccessの設定によります。設定を変えたら新しいユーザーのログインで確かめ、拒否されたら`OIDC_REQUIRE_EMAIL_VERIFIED=false`に戻してください。

Accessで`OIDC_REQUIRE_GOOGLE_HD`を使う場合は、同じ「Add claims」でGoogle IdPから取り込んだ`hd`を同じ名前で渡してください。Gmailのアカウントには`hd`がないので、このクレームはRequiredにしないでください。

パスワード認証からOIDC認証に切り替えるときは、ユーザーがすでにいるので`INITIAL_ADMIN_EMAIL`は使われません。切り替える前に、各ユーザーのメールアドレスがIdPのメールアドレスと一致しているか確かめてください。一致した人は初回のOIDCログインで紐付きます。特に管理者のメールアドレスが一致していないと、誰もユーザーを追加できなくなります。ユーザーのメールアドレスはあとから変えられないので、一致しない人はIdPのメールアドレスで追加し直してください。

**`ALLOWED_EMAILS`を使っていた版から更新するとき:** 以前のOIDC認証では、`ALLOWED_EMAILS`に合う人は初回ログインでユーザーが自動で作られました。更新後は「ユーザー管理」に登録済みの人しかログインできません。

- 更新する前に「ユーザー管理」の一覧と`ALLOWED_EMAILS`を見比べ、ログインさせたくないユーザーを削除してください。一覧にいるユーザーは`ALLOWED_EMAILS`と関係なくログインできるようになります。
- ドメインの指定や`*`で新しい人が自分でログインできていた運用では、管理者が「ユーザー管理」で追加するまで、新しい人は403になります。
- 更新後は`ALLOWED_EMAILS`は読まれないので、削除してかまいません。

### 多要素認証（パスワード認証）

パスワード認証では、パスワードに加えてパスキー（WebAuthn）や認証アプリ（TOTP）を使えます。ログイン画面の「多要素認証の設定」（`/auth/mfa/manage`）から登録します。登録すると、失くしたときのためのリカバリーコードが表示されます。認証方法とは別の場所に保管してください。

- パスキーを使うには`APP_ORIGIN`が要ります。パスキーは`APP_ORIGIN`のOriginで開いたときだけ使えます。`*.workers.dev`のURLや別のホスト名で開いたときは使えません。
- 認証アプリを使うには`PASSWORD_MFA_KEY`が要ります。変えると登録済みの認証アプリが使えなくなります（使っていないリカバリーコードで登録し直せます）。
- `PASSWORD_MFA_POLICY`が`optional`なら、登録するかどうかは各自が決めます。`admins`なら管理者、`all`なら全員がログイン時に登録を求められます。`all`は初期設定画面で作る最初の管理者にも効きます。登録した人は、どの設定でもログインのたびに多要素認証を使います。
- 認証方法とリカバリーコードをすべて失くした人は、ほかの管理者が「ユーザー管理」の「多要素認証をリセット」で登録を消せます（下記）。

管理者が1人だけで、その管理者が認証方法とリカバリーコードをすべて失くしたときは、D1の行を直接削除します。メールアドレスは小文字で保存されています。

```sh
wrangler d1 execute <DATABASE> --remote --command "
DELETE FROM mfa_pending WHERE user_id = (SELECT id FROM users WHERE email = 'admin@example.com');
DELETE FROM mfa_recovery_codes WHERE user_id = (SELECT id FROM users WHERE email = 'admin@example.com');
DELETE FROM mfa_credentials WHERE user_id = (SELECT id FROM users WHERE email = 'admin@example.com');
DELETE FROM mfa_accounts WHERE user_id = (SELECT id FROM users WHERE email = 'admin@example.com');
"
```

この操作ではセッションとMCPの接続は切れません。

## ユーザーを管理する

管理者はWebの「ユーザー管理」（`/users`）でユーザーの一覧を見られます。ここではユーザーを追加したり、ロールを変えたり、ログアウトさせたり、ユーザーを削除したりできます。パスワード認証ではパスワードの再設定と多要素認証のリセットもできます。

- パスワード認証でユーザーを追加するとき、パスワードを空欄にすると招待リンクが発行されます。本人がリンクを開いてパスワードを決めるとログインできます。リンクは7日間、1回だけ使えます。リンクは発行したときにしか表示されないので、その場でコピーして本人に伝えてください。
- 招待リンクのOriginは、有効な`APP_ORIGIN`があればそれ、なければ管理者が開いている画面のOriginです。
- 招待リンクを失くしたときや期限が切れたときは、「招待リンクを再発行」で新しいリンクを発行できます。前のリンクは使えなくなります。管理者がパスワードを再設定しても、招待は使われたことになります。
- OIDC認証でユーザーを追加すると、その人はIdPでログインすると使えるようになります（「OIDC認証にする」を参照）。
- 「多要素認証をリセット」は、その人の認証方法（パスキー・認証アプリ・リカバリーコード）をすべて削除し、すべての端末でログアウトさせます。MCPの接続も切れます。パスワードはそのままです。リセット後はパスワードだけで新しい認証方法を登録できるので、本人確認をしてから実行し、すぐにログインして登録してもらってください。自分自身の多要素認証はリセットできません。

ユーザーを削除するときは次の点に注意してください。

- ユーザーを削除すると、その人の個人スペースも中身（ページ・ゴミ箱のページ・フォルダ・添付ファイル）ごと削除されます。元に戻せません。D1をTime Travelで戻しても、R2から消えた添付ファイルは戻りません。
- ほかのスペースでその人が作成・編集したページは残ります。
- メンバー指定のスペースのメンバーからも外れます。
- 自分自身は削除できません。最後の管理者を削除することも一般に戻すこともできません。
- まだログインしていない人を削除すると、招待の取り消しになります。
- OIDC認証の場合、削除した人はログインできなくなります。もう一度使ってもらうには、ユーザー管理で追加し直します（新しいユーザーとして作られます）。

## メンバー指定のスペース

管理者がWebでスペースを作るときに「メンバー指定」を選ぶと、選んだユーザーと管理者だけが見られるスペースになります。見られる人はページの閲覧も編集もできます。

- メンバーを選べるのは管理者だけで、Webからだけ変えられます。スペースのメニューの「メンバーを編集」で選び直します。MCPからはメンバーを見ることも変えることもできません。
- 管理者はメンバーに選ばなくても見られます。管理者をメンバーに選んでおくと、一般に戻したあとも見られます。
- メンバーから外したり管理者を一般に戻したりすると、その人は次の操作から見られなくなります（MCPを含む）。ユーザーを削除するとメンバーからも外れます。
- 外した人のブラウザには、それまでに開いた添付ファイルが最大5分キャッシュに残ります。
- スペースの種類は作成後に変えられません。


Web画面でページの本文（Markdown）を表示するときは、本文中のHTMLをタグとして解釈せずに書いたとおりの文字で表示します。外部の画像は表示しません。

本文のコードブロックは右上のボタンでコードだけをコピーできます。マウスで操作するときは、コードブロックにポインタを乗せるとボタンが出ます。

Webでページを作成・編集している間は、入力中の内容がブラウザ（localStorage）に下書きとして保存されます。この下書きはログアウトしても消えないので、同じブラウザでログインした別の人に見える可能性があります。同じページを複数のタブで編集すると下書きどうしが上書きし合います。共有PCでは使わないでください。

## 添付ファイル

ページには画像（PNG・JPEG・GIF・WebP）とPDFを添付できます。Webではページの編集画面の「添付ファイル」から追加して（1ファイル10MBまで）、本文にMarkdownとして挿入できます。新しいページは保存してから編集画面で添付してください。MCPからも添付できます（1ファイル2MBまで）。

- ファイルの種類は中身から判定します。SVGやHTMLのようにスクリプトを含められる形式は添付できません。ファイル名の拡張子が種類と合わないときは種類の拡張子を末尾に足します。
- 添付ファイルを見られるのはそのページを見られる人だけです。ページを別のスペースへ移すと添付ファイルも一緒に移ります。
- ゴミ箱にあるページの添付ファイルは見られません。ページを元に戻すとまた見られるようになります。
- 添付ファイルの削除は元に戻せません。本文から参照している箇所は表示されなくなります。
- ファイルの中身はR2に保存します。ページを完全に削除すると添付ファイルもR2から削除されます。30日たって自動で削除されたページの添付ファイルは、ページと同じ日次の処理で消えます。管理者がゴミ箱から完全に削除したページの添付ファイルは、次の日次の処理（毎日03:00 JST）で消えます。アップロードの途中で失敗して残ったファイルは、24時間たったあとの日次の処理で消えます。

## トップに表示するページ

ホーム画面（`/`）ではスペースの一覧の上にページを1つ表示できます。管理者が全員スペースのページを開いて「トップに表示」を押すと、そのページが全員のホーム画面に出ます。リンク集のようにチームの入口になるページに向いています。

- 選べるのは全員スペースのページだけです。表示中のページを全員スペース以外へ移したりゴミ箱に入れたりすると表示されなくなり、戻すとまた表示されます。
- ページを完全に削除すると設定も外れます。
- 表示するページはほかのページと同じように編集できます。MCPからも`update_page`で更新できます。どのページを表示するかはWebでしか選べません。

## PDFで出力

ページの「…」メニューの「PDFで出力」から、ページをA4のPDFにできます。プレビューを見ながら体裁と表紙の項目を入力して出力します。入力した内容は保存されません。

- 体裁は「正式（表紙あり）」と「シンプル」の2種類です。正式では1ページ目が表紙になり、タイトル・宛先・日付・版数・発行者・機密表示を載せます。シンプルでは本文の先頭にタイトルを置きます。
- 本文のページの下にページ番号を、機密表示を入力したときは右上に機密表示を入れます。ページ番号の総数には表紙を含みます。
- 発行者と機密表示の既定値は、管理者が画面の「発行者と機密表示を既定として保存」で全員分を保存できます。
- 出力の方法は2つです。既定ではブラウザの印刷ダイアログで「PDFに保存」を選びます。ページ番号と機密表示のヘッダーはChromeでのみ入ります。設定で`PDF_RENDERER`を`browser`にすると、サーバー（Browser Rendering）で作ったPDFをダウンロードできます。このときもブラウザの印刷を使えます。
- サーバーで作るPDFには、このサイトにある画像（添付ファイル）だけが入ります。ほかのサイトの画像は代わりのテキストになります。
- サーバーで作る場合、ログインしている人は見られるページを指定すれば任意のHTMLをPDFにできます。PDFを作るブラウザではJavaScriptを動かさず、外部への通信もさせません。回数の制限はありません。

## ページどうしのリンク

ページの末尾の「このページへのリンク」には、本文でそのページへリンクしているページが並びます。出るのは見ている人が見られるページのうちゴミ箱にないものだけです（新しく更新された50件まで）。

- ページのツールバーの「Markdownのリンクをコピー」を押すと`[タイトル](/pages/{id})`の形のMarkdownがコピーされます。ほかのページの本文に貼り付けてください。チャットなどに貼るときは「URLをコピー」で`https://…/pages/{id}`の完全なURLをコピーできます。タイトルの横のボタンではタイトルの文字列だけがコピーされます。「本文のテキストをコピー」では、表示されている本文の文字だけ（Markdownの記号を除いたもの）がコピーされます。
- 本文に`/pages/{id}`を含むものはすべてリンクとして数えます。`https://…/pages/{id}`のような完全なURLも、コードブロックの中も含みます。
- MCPではAIが`[タイトル](/pages/{id})`の形でリンクを書きます。リンクしているページを探すときは`search_pages`で`/pages/{id}`を検索します。この検索結果には、タイトルが一致したページとそのページ自身も含まれます。

## MCPで接続する

生成AIのアプリからMCPでスペースとページを読み、ページを作成・更新できます。ページのタイトルと本文を文字列で検索することもできます。接続はログインしたユーザー本人として行われます。Webと同じく、そのユーザーがアクセスできるスペースしか見えません。

フォルダの作成・名前変更・移動・削除もMCPからできます。削除できるのは、中にフォルダと（ゴミ箱以外の）ページがないフォルダだけです。

ページとフォルダは移動用のツール（`move_page`と`move_folder`）で別のスペースへ移せます。フォルダは中のフォルダとページ（ゴミ箱のページを含む）ごと移ります。個人スペースから全員スペースへのように見られる人が増える移動では、AIが利用者に確認してから`acknowledge_wider_visibility`を付けて呼ばないと失敗します。見られる人の広さは「個人 < 管理者のみ < メンバー指定 < 全員」の順に数えます。メンバー指定のスペースから別のメンバー指定のスペースへの移動も同じく確認が要ります（メンバーの顔ぶれは比べません）。

MCPからはページへのファイルの添付（`upload_attachment`、2MBまで）と添付ファイルの一覧（`list_attachments`）も使えます。添付したファイルを本文に入れるには、返されたMarkdownを`update_page`で本文に書き足します。添付ファイルの削除はWebからしかできません。

MCPからページを削除するとゴミ箱に移り、30日のあいだは元に戻せます。完全に削除できるのは管理者だけで、Webのゴミ箱から行います。上書きする前の内容は編集履歴として新しい20版まで残り、そこから戻せます。ゴミ箱から完全に削除したページと30日たって自動で削除されたページは、履歴ごと消えるので戻せません。

接続先のURLは`<URL>/mcp`です（OIDC認証では`<APP_ORIGIN>/mcp`）。Claudeのカスタムコネクタで追加する手順は次のとおりです。

1. Claudeの「設定」→「コネクタ」でカスタムコネクタを追加する。
2. URLに`<URL>/mcp`を入れて接続する。
3. 開いたブラウザでlibrenoにログインし、接続を許可する。

Claude Codeで追加する手順は次のとおりです。OIDC認証では`<URL>/mcp`の代わりに`<APP_ORIGIN>/mcp`を使います。

1. `claude mcp add --transport http libreno <URL>/mcp`を実行する。
2. Claude Codeで`/mcp`を開き、librenoを選んで認証する。
3. 開いたブラウザでlibrenoにログインし、接続を許可する。

許可の画面は接続のたびに表示されます。接続の有効期限は30日です。期限が切れたらもう一度接続してください。

管理者がユーザーのセッションを失効させたとき、管理者がパスワードを再設定したとき、管理者が多要素認証をリセットしたとき、本人がパスワードを変更したときは、そのユーザーのMCPの接続もすべて切れます。その時刻までに許可した接続は`/mcp`で拒否されるので、接続情報を保存しているKVの反映が遅れて取り消しから漏れた接続も使えません。Webからログアウトしても、MCPの接続は切れません。

デプロイすると、MCPの接続情報を保存するKVネームスペースが1つ作られます。

## 更新する

ボタンで作ったリポジトリには、このリポジトリの更新が自動では届きません。次の手順で取り込んでください。pushするとWorkers Buildsがマイグレーションを適用してからデプロイします。

```sh
git remote add upstream https://github.com/i2bskn/libreno.git  # 初回だけ
git fetch upstream
git merge upstream/main
git push
```

`wrangler.jsonc`を自分で変更している場合は、マージで競合することがあります。

**添付ファイルの機能が入る前の版から更新するときも、先にCloudflareのダッシュボードでR2を有効にしてください。** R2を有効にせずに更新してデプロイが失敗したときは、R2を有効にしてから再デプロイすれば動きます。先に適用されたマイグレーションは表を追加するだけなので、そのままで問題ありません。

## ローカルで開発する

ログイン、ユーザー管理、MCPのOAuth認可サーバーは[`@i2bskn/workers-app-core`](https://github.com/i2bskn/workers-app-core)を使っています（`src/core.ts`）。

Node.jsとpnpmが必要です。

```sh
pnpm install
cp .dev.vars.example .dev.vars   # JWT_SECRET を設定する
pnpm db:migrate:local
pnpm dev
```

`pnpm dev`はWeb画面（`client/`）をビルドしてから`wrangler dev`を起動します。`client/`のファイルを変えると自動で再ビルドされます。HMRは無いので、ブラウザを再読み込みしてください。

CookieにSecure属性と`__Host-`接頭辞を使っているので、`http://localhost`ではSafariでログインできません。ChromeかFirefoxを使ってください。

| コマンド | 内容 |
| --- | --- |
| `pnpm test` | テスト |
| `pnpm typecheck` | 型チェック（サーバーとWeb画面） |
| `pnpm build:client` | Web画面を`dist/client`にビルドする |
| `pnpm db:generate` | スキーマからマイグレーションを作る |
| `pnpm run deploy` | 本番のD1にマイグレーションを適用してデプロイする（`pnpm deploy`はpnpm自体のコマンドなので`run`を付けてください）。Cloudflareのアカウントが複数あるときは`CLOUDFLARE_ACCOUNT_ID`にデプロイ先のアカウントIDを指定してください |
