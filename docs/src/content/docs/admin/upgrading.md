ボタンで作ったリポジトリには、このリポジトリの更新が自動では届きません。次の手順で取り込んでください。pushするとWorkers Buildsがマイグレーションを適用してからデプロイします。

```sh
git remote add upstream https://github.com/i2bskn/libreno.git  # 初回だけ
git fetch upstream
git merge upstream/main
git push
```

`wrangler.jsonc`を自分で変更している場合は、マージで競合することがあります。

## 版ごとの注意

### 添付ファイルの機能が入る前の版から更新するとき

先にCloudflareのダッシュボードでR2を有効にしてください。R2を有効にせずに更新してデプロイが失敗したときは、R2を有効にしてから再デプロイすれば動きます。先に適用されたマイグレーションは表を追加するだけなので、そのままで問題ありません。

### パスワードのハッシュがscryptになる版から更新するとき

既存のユーザーのパスワードはPBKDF2のまま使えます。更新後に新しく設定したパスワードと、登録されていないメールアドレスでのログインの確認はscryptになります。

既存のユーザーがいる間は、ログインの応答時間から登録済みのメールアドレスが分かることがあります。避けたい場合は更新の前に変数`PASSWORD_HASH_ALGORITHM`を`pbkdf2`にしてください。このとき`PASSWORD_PBKDF2_ITERATIONS`は設定せず、既定の100000のままにしてください。既存のハッシュは100000回で作られているので、回数を変えると応答時間の差がまた生じます。

OIDC認証ではパスワードのハッシュを使わないので関係ありません。

### ALLOWED_EMAILSを使っていた版から更新するとき

OIDC認証で`ALLOWED_EMAILS`を使っていた場合は、更新の前に[OIDC認証にする](/libreno/admin/oidc/#allowed_emailsを使っていた版から更新する)の手順でユーザーを確かめてください。

## バックアップ

バックアップは各自で行ってください。D1はTime Travelで過去の時点に戻せます。`wrangler d1 export`でSQLとして書き出すこともできます。
