title: 動作環境
description: Workersの無料プランで動く範囲と、Workers Paidが必要になる使い方。
---

Workersの無料プランでも動きます。ただし、次の使い方では無料プランの上限を超えることがあります。

| 機能 | 無料プランで動くか |
| --- | --- |
| ページを開く（D1の読み取り） | ページ数と開く回数によります（下記） |
| Webからの添付ファイルのアップロード | 上限に収まります |
| パスワード認証のログイン | 上限を超えます（下記）。計測では打ち切られませんでした |
| MCP | 上限を超えます。Workers Paidを使ってください |
| 日次の削除処理（Cron Trigger） | 上限を超えて失敗することがあります |
| サーバーでのPDF出力 | 1日10分まで |

## パスワードのハッシュ

パスワードのハッシュは1回で無料プランのCPU時間の上限（1リクエスト10ms）を超えます（既定のscryptで約150〜200ms。`PASSWORD_HASH_ALGORITHM=pbkdf2`の10万回なら16〜56ms）。2026年11月の計測では無料プランでも打ち切られませんでしたが、保証はありません。

- ログインがCPU時間の上限で失敗する場合は`pbkdf2`にして回数（`PASSWORD_PBKDF2_ITERATIONS`）を下げるか、Workers Paidを使ってください。
- OIDC認証ではパスワードのハッシュを使いません。
- 方式を変えても既存のパスワードのハッシュは作り直されません。scryptから`pbkdf2`に戻しても、既存のscryptのハッシュを確かめるCPU時間はパスワードを設定し直すまで変わりません。既存のユーザーがいる間に方式を変えるときの注意は[更新する](/libreno/admin/upgrading/#パスワードのハッシュがscryptになる版から更新するとき)を参照してください。

## MCP

MCPは接続するたびにCPU時間を20〜40ms使い、ファイルの添付では1回60ms以上使うこともあるので、無料プランの上限を超えます。MCPを使う場合はWorkers Paidを使ってください。

## 添付ファイル

Webからの添付ファイルのアップロードは10MBのファイルでもCPU時間が4〜7msで、無料プランの上限に収まります（ファイルをメモリに読まずにR2へ流すため）。

## D1の読み取り

そのページへリンクしているページを探すため、ページを開くたびに見られるページの本文をすべてD1から読みます（読み取り行数は1回あたりページ数とほぼ同じです）。ページが1,000件なら、1日5,000回ページを開くと無料プランの上限（1日500万行）に達します。

## Cron Trigger

Cron Triggerを1日1回使い、ゴミ箱に30日あったページと持ち主のなくなった添付ファイルを消します。Workersの無料プランでも使えますが、アカウントあたりのCron Triggerの上限のうち1つを使います。

消すものがない日でもCPU時間を11ms使ったので（1回の計測）、無料プランの上限（1回10ms）を超えて失敗することがあります。失敗しても次の日の実行で同じものを消します。失敗が続く場合はWorkers Paidを使ってください。

## Browser Rendering

ページのPDF出力をサーバーで行う場合（`PDF_RENDERER=browser`）はBrowser Rendering（Browser Run）を使います。無料プランではブラウザを使える時間が1日10分までです。超えるとその日はサーバーでPDFを作れないので、ブラウザの印刷を使ってください。Browser Runの利用量はアカウント内のほかのWorkerと共有されます。

## プレビューURL

プレビューURLは無効にしています。マイグレーションを適用していないコードが本番のD1に触れるのを防ぐためです。
